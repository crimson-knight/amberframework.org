# Seek adventure with Amber

Build a real web app with the supported, release-gated web foundation. This beta exercises the complete release journey: install, build, follow a guide, make a change with your coding assistant, update, and bring back evidence.

Contributions require a coding assistant. You own the idea, constraints, evidence review, submission and acceptance. Your assistant inspects the repository, reproduces behavior, implements accepted work, runs checks and prepares the proposal.

Start with an organization client portal, inventory tracker or service request desk. Recommended business templates, migration guides and measured operating ranges are in preparation. Current template capacity remains unmeasured; published core research retains its own workload scope. Default memory jobs are process-local, so reliable reminders require a verified delivery adapter.

Use [the installation guide](/docs/v2/getting-started/installation), [docs MCP](/docs/v2/guides/ai-assistants/mcp), Minecart's agent context and [contributor guidance](/docs/v2/contributing). Build one page and one editable record, restart and verify persistence, then inspect one assistant-built change.

Bring proposals, reports and showcase requests directly to [GitHub issues](https://github.com/amberframework/amber/issues). Search existing issues, prepare exact versions, expected/actual behavior and reproduction evidence, review it, and open a proposal before its linked PR. Join [Discord](https://discord.gg/vwvP5zakSn) for human community conversation; actionable contributions return to GitHub.

The proposed showcase confirms your permission and agreed credit in the issue before publication. Web apps are the first audience; mobile follows.
